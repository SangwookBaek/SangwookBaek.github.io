## Intro

추천 시스템을 직접 만들고 싶다고 생각하면, 처음에는 모델부터 떠올렸다. 임베딩을 만들고, Vector DB를 붙이고, API를 열면 되는 줄 알았다.

근데 조금만 구체적으로 적어보니 그 위에 얹혀야 하는 것들이 너무 많았다. 백엔드와 프론트엔드, PostgreSQL과 Redis, 크롤러, Airflow, Docker, 모니터링. 모델을 한 번 돌려보는 환경이 아니라, 계속 쌓이고 계속 고쳐지는 환경이 필요했다.

그래서 홈 서버를 구성하기로 했다. 이번 글에서는 어떤 부품을 샀는지보다, 왜 이 정도 구성이 필요하다고 판단했는지를 먼저 정리해보려고 한다.

## GPU 서버를 빌리면 되지 않나?

사실 처음에는 Colab이나 RunPod 같은 GPU 서버를 쓰면 된다고 생각했다. 실험 하나를 끝내기에는 훨씬 편하다. 필요한 순간에만 GPU를 빌리면 되니까 비용도 예측하기 쉽다.

근데 내가 만들고 싶은 건 단발성 모델 실험만은 아니었다.

크롤링한 상품 데이터를 넣고, ETL을 돌리고, 임베딩을 다시 만들고, DB와 API를 같이 올려두는 과정 자체를 익히고 싶었다. 어느 날은 학습을 돌리고, 어느 날은 추천 API를 고치고, 어느 날은 데이터 파이프라인이 왜 멈췄는지 봐야 한다.

클라우드에서 각각 할 수는 있다. 다만 환경이 매번 사라지고, 네트워크와 스토리지는 이미 준비되어 있다는 전제 위에서 작업하게 된다. 나는 그 전제 아래에 무엇이 있는지도 같이 보고 싶었다.

그래서 결론은 꽤 단순했다. 지금 필요한 것은 큰 인프라가 아니라, 하나의 지속되는 실험장이다.

## 그러면 CPU는 어느 정도가 필요할까?

GPU를 두 장 넣는다고 해서 나머지는 아무거나 써도 되는 건 아니었다. 추천 시스템을 만들 때 GPU가 필요한 순간은 분명 있지만, 데이터 처리나 크롤링, 여러 컨테이너를 동시에 띄우는 작업은 CPU와 메모리에 더 많이 기대게 된다.

그래서 CPU는 Ryzen 9 9900X로 골랐다. 12코어 24스레드면 학습을 돌리는 옆에서 크롤러나 DB가 완전히 멈추지는 않을 것 같았다. 물론 아직 사용량을 측정한 뒤에 고른 수치는 아니다. 다만 처음부터 CPU가 병목이 되어 전체 환경을 다시 뜯어고치는 상황은 피하고 싶었다.

메모리는 DDR5 5600 64GB(32GB x 2)로 잡았다. PostgreSQL, Redis, Docker 컨테이너, 개발 도구를 같이 띄우면 32GB는 생각보다 빨리 답답해질 것 같았다. 반대로 지금 단계에서 128GB는 실제 사용처보다 불안감에 가까운 선택처럼 느껴졌다.

이 선택이 맞는지는 결국 운영하면서 알게 될 것 같다. 지금은 확장할 수 있는 메인보드를 고르고, 당장 필요한 여유를 확보하는 쪽을 택했다.

## GPU 두 장은 왜 필요한가?

GPU는 RTX 5060 Ti 16GB 두 장으로 구성했다.

처음에는 한 장으로도 충분하지 않을까 싶었다. 그런데 하나는 임베딩이나 모델 실험을 돌리고, 다른 하나는 서빙 또는 다른 실험에 쓸 수 있으면 환경을 끄고 켜는 일이 줄어든다. 특히 VRAM 16GB는 아주 큰 모델을 돌리기엔 부족할 수 있지만, 상품 임베딩이나 중간 규모의 실험을 시작하기에는 현실적인 선이라고 봤다.

여기서 중요한 건 GPU 자체보다 메인보드의 슬롯 구성이었다. ASUS ROG STRIX B650E-E는 두 GPU 슬롯을 x8/x4로 쓸 수 있다. 두 장을 꽂았을 때 두 번째 카드가 아예 제 성능을 못 내는 구성은 피하고 싶었다.

![ASUS ROG STRIX B650E-E]({{ page.img_base }}/motherboard.png){: width="500" }

다만 이게 멀티 GPU 학습을 제대로 하겠다는 의미는 아니다. 지금은 작업을 나눠 쓸 수 있는 여지를 만든 쪽에 가깝다. 실제로 두 GPU가 필요할 만큼의 작업을 하게 될지는 아직 모른다.

## 결국 이렇게 구성했다

| 구분 | 구성 |
| --- | --- |
| CPU | AMD Ryzen 9 9900X (12코어 / 24스레드) |
| 메모리 | DDR5 5600 64GB (32GB x 2) |
| GPU | RTX 5060 Ti 16GB x 2 |
| 메인보드 | ASUS ROG STRIX B650E-E (PCIe x8/x4) |
| 저장장치 | Samsung 990 Pro 2TB |
| 파워 | 1200W PSU |

![부품 구성]({{ page.img_base }}/components.jpeg){: width="500" }

저장장치는 Samsung 990 Pro 2TB를 넣었다. 데이터셋, Docker 이미지, DB 볼륨이 전부 한 곳에 쌓이게 될 테니 속도도 필요했지만, 지금은 용량보다 백업 전략을 먼저 고민해야 할 것 같다. SSD 하나가 곧 서버 전체의 데이터가 되는 구조이기 때문이다.

1200W 파워도 같은 맥락이다. 두 GPU가 항상 최대 전력을 쓰지는 않겠지만, 전원이 모자라는 상태에서 불안하게 운영하고 싶지는 않았다.

## 이제부터가 더 궁금하다

하드웨어를 고른다고 서버가 생기는 건 아니다. OS를 올리고, SSH로 밖에서 접속하고, 컨테이너를 어떻게 나눌지 정해야 한다. GPU 드라이버와 CUDA, Docker가 서로 어떤 식으로 얽히는지도 직접 만나봐야 한다.

지금 구성은 정답이라기보다 출발점이다. 이 서버가 정말 추천 시스템을 위한 지속적인 환경이 될지, 아니면 생각보다 과한 개인 PC가 될지는 다음 작업들에서 드러날 것 같다.
