## Intro

홈 서버를 켜고 가장 먼저 하고 싶었던 건 밖에서도 접속하는 것이었다. 집 Wi-Fi에서는 SSH가 잘 됐다.

```bash
ssh user@192.168.x.x
```

그런데 휴대폰 핫스팟으로 바꾸자 바로 접속이 안 됐다. 서버가 꺼진 것도 아니고, SSH 설정을 잘못한 것도 아닌 것 같았다. UFW도 확인해봤는데 비활성화 상태였다.

그때 처음으로 `192.168.x.x`가 “서버의 주소”라는 생각이 조금 이상해졌다. 집 안에서는 주소인데, 왜 집 밖에서는 아무 의미가 없을까?

## 같은 서버인데 주소가 두 개인 이유

서버에서 아래 두 명령을 실행해 봤다.

```bash
ip addr
curl ifconfig.me
```

첫 번째에서 나오는 `192.168.x.x`는 공유기 안에서만 쓰는 사설 IP였고, 두 번째에서 나온 값이 외부에서 보이는 공인 IP였다.

집 네트워크를 단순하게 그리면 이런 모양이었다.

```text
인터넷
  ↓
공인 IP를 가진 공유기
  ↓
192.168.x.x를 가진 내 서버
```

외부에서 공인 IP로 들어오는 패킷을 공유기가 받는 것까지는 이해됐다. 문제는 그 다음이었다. 공유기는 집 안에 노트북도 있고, 휴대폰도 있고, 서버도 있다. 그냥 “22번 포트로 왔다”고 해서 어느 기기로 보내야 하는지 알 수 없다.

그러면 공유기에게 그 규칙을 알려줘야 했다. 그게 포트포워딩이었다.

![홈 네트워크 토폴로지](/assets/img/posts/ssh-external-access/network-topology.png)

## 우리 집에서는 어느 장비가 공유기일까?

여기서 한 번 더 헷갈렸다. 집에는 장비가 하나가 아니었다. 현관 통신함 쪽에 GNT2400이 있고, 방 쪽에는 GW-ME6110 무선 AP와 셋톱박스가 있었다.

처음에는 Wi-Fi를 뿌리는 장비에서 포트포워딩을 찾았다. 그런데 외부에서 들어오는 공인 IP를 실제로 받는 장비는 따로 있을 수 있다. 결국 통신함에 있는 GNT2400의 관리 화면에 들어가야 했다.

관리자 비밀번호도 일반적인 공유기 초기 비밀번호가 아니었다. 장비 MAC 주소의 마지막 6자리에 `_admin`을 붙이는 방식이었다. 이런 정보는 제품 설명서나 통신사 장비 안내를 확인하지 않으면 추측만으로 찾기 어렵다.

## 그래서 22번 포트를 서버로 보냈다

GNT2400 관리 화면에서 TCP 22번 포트가 서버의 사설 IP로 가도록 규칙을 추가했다.

```text
외부 공인 IP:22
        ↓
서버 사설 IP:22
```

여기서 한 가지 더 신경 쓸 부분이 있었다. 서버의 사설 IP가 DHCP 때문에 바뀌면 이 규칙은 다른 기기를 가리키게 된다. 지금은 서버 IP를 고정해서 사용했고, 나중에는 DHCP 예약으로 관리하는 편이 더 안전할 것 같다.

외부 테스트는 Wi-Fi를 끄고 휴대폰 핫스팟에서 했다.

```bash
ssh user@<공인-IP>
```

환경에 따라 IPv6로 먼저 붙으려다 헷갈리는 경우가 있어, 필요할 때는 `-4` 옵션으로 IPv4를 명시했다.

```bash
ssh -4 user@<공인-IP>
```

접속이 되자 신기하긴 했지만, 동시에 공개한 것이 하나 생긴 셈이기도 했다. 이제 집 밖 누구나 공인 IP의 22번 포트를 두드릴 수 있다.

## 연결은 됐는데, 이게 운영 방식일까?

포트포워딩을 하면서 NAT가 왜 필요한지, 사설 IP와 공인 IP가 왜 구분되는지는 조금 감이 왔다. 그런데 이 방식에는 여전히 찜찜한 부분이 있다.

공인 IP는 바뀔 수 있고, 외부에 SSH 포트를 열어 둬야 한다. 당장은 키 인증을 쓰고 비밀번호 로그인은 막아야 할 것 같다. IP가 바뀌는 문제는 DDNS로 풀 수 있다.

다만 이 모든 걸 계속 관리하는 것이 홈 서버에 가장 자연스러운 접속 방식인지는 별개 문제다. 포트포워딩을 이해한 다음에는, 굳이 포트를 열지 않고 접속하는 방법도 찾아보게 됐다.
